# 《福瑞快打》美术与特效协作规范

本文是角色、怪物、场景、界面和战斗特效的共同制作约定。目标是让新增内容即使由不同协作者完成，也能保持同一套「圆润福瑞角色 + 暮色森林舞台 + 清晰战斗符号」的画风。

## 1. 总体气质

- 关键词：温暖、圆润、轻奇幻、手绘感、低压迫、读图迅速。
- 画面采用二到三层明度：深青或深棕作为轮廓与阴影，中间色表现主体，暖金、青绿或冰蓝作为能量高光。
- 角色和怪物使用夸张轮廓传达职业，不依赖写实纹理；在 Canvas 小尺寸下，先保证剪影可识别，再添加眼睛、徽记和局部高光。
- UI 主题可以改变界面配色，局内地图、花草、建筑和角色模型保持自己的视觉系统；地图美术由地图数据决定。

## 2. 角色建模

- 角色比例以大头、短肢、清晰耳朵和蓬松尾巴为基础。脸部使用柔和曲线，眼睛占脸部主要视觉焦点。
- 角色外观拆成毛色、服装、头饰、眼睛、体型五个层级；每层都要有深色描边或明暗分区，避免颜色混成一团。
- 毛色使用主色 + 深色阴影 + 少量奶油色部位；服装使用低饱和中间色，扣件、枪械和眼睛用高亮色作为焦点。
- 默认描边为深青黑色，线宽随模型尺寸缩放。小于约 22px 的局内模型省略毛纹和细缝，只保留耳朵、眼睛、尾巴、服装块面和武器轮廓。
- 待机动画优先使用尾巴轻摆、躯干呼吸、眨眼、抖耳和围巾摆动；脚底位置保持稳定，动画只改变局部姿态，不改变碰撞坐标。
- 攻击动画应通过枪口闪光、身体轻微前倾和弹道拖尾表达，避免大幅位移遮挡玩家位置。

## 3. 怪物建模

怪物必须先表达行为，再表达颜色。新增怪物至少提供一个独有剪影和一个战斗标记：

| 类型 | 造型语言 | 必须保留的识别符号 |
|---|---|---|
| 普通近战 | 圆润躯干、獠牙或厚重下颚 | 红色系、朝向玩家的眼睛 |
| 快速近战 | 细长身体、尖耳、后掠姿态 | 橙色系、腿部或尾部速度线 |
| 远程 | 兜帽、法杖或远程器具 | 紫色系、手上或身侧的发射物 |
| 自爆 | 圆鼓身体、引线、闪烁火星 | 棕色系、顶部红色倒计时灯 |
| 猎人 | 面罩、弓弩或瞄准环 | 粉红系、半圆瞄准标记 |
| 治疗 | 长袍、十字或叶片徽记 | 绿色系、治疗范围环 |
| 护盾 | 厚甲、肩甲、盾牌 | 青蓝系、外侧盾牌与护盾环 |
| 召唤 | 长袍、法杖、悬浮核心 | 紫色系、法杖和召唤符文 |
| 精英 | 更厚轮廓、八向尖刺或护甲板 | 紫色系、护盾与精英尖刺 |
| Boss | 体型至少为普通怪约 2 倍 | 皇冠/角、种类专属武器或核心 |

Boss 的颜色只用于第一眼分类，真正的技能差异由造型道具和地面预警表达：冲锋者使用角和前倾姿态，弹幕者使用环形核心，召唤者使用法杖，分裂者使用中央裂纹徽记。

## 4. 场景与 UI

- 暮色森林场景使用深青、苔绿、树皮棕和暖金月光；背景层次从远到近依次为雾、山林剪影、地面纹理、植物和可交互建筑。
- 地面装饰使用确定性坐标和低对比度纹理，不能抢过角色、敌人和掉落物。建筑需要有明确的碰撞轮廓和受击反馈。
- UI 面板使用半透明深色底、细边框、圆角和单一强调色。主题只替换变量，不新增局内世界色彩耦合。
- 信息优先级固定为：玩家生命/护盾 > Boss 与危险预警 > 当前等级与经验 > 构筑标签 > 装饰信息。

## 5. 特效规范

- 特效采用「核心 + 光晕 + 方向拖尾」三层结构。核心负责命中位置，光晕负责能量类型，拖尾负责速度方向。
- 子弹和技能的颜色语义保持稳定：火焰橙红、雷电青白、冰霜浅蓝、召唤物青绿/紫、敌方危险珊瑚红。
- 命中特效应短促，通常 0.15 至 0.45 秒；持续状态用环、火焰、霜晶或符文表达，不使用无法解释的漂浮光球。
- Boss 技能必须先预警再结算：地面方向条、范围圈、读条或缺口至少提前 0.5 秒出现。结算时使用一次明确的屏幕震动、音效和伤害数字。
- 精简环境特效和系统减少动态效果时，保留攻击本体、危险预警和必要状态图标，关闭萤火、拖尾、震屏和多余光晕。

## 6. Canvas 实现约定

- 绘制函数命名使用 `drawXxxModel`、`drawXxxEffect`，更新函数使用 `updateXxx`；模型绘制不修改实体坐标、生命或碰撞半径。
- 所有 `save()` 必须有对应的 `restore()`；绘制前明确 `translate`、`rotate` 和 `globalCompositeOperation`，结束时恢复。
- 新模型至少在 320×568、390×844 和 900×450 三种尺寸检查；需要覆盖正常、受击、死亡、燃烧、冰冻、护盾和 Boss 阶段状态。
- 特效必须有生命周期和回收条件，禁止依赖数组挤出旧对象；暂停、升级、后台恢复后不得出现过期残影。
- 新增颜色优先写在模型局部常量中；界面主题颜色写入 `themes.css` 或 `UI_THEMES`，不要从 UI 主题读取局内地形颜色。

## 7. 协作验收清单

- 剪影在缩小到约 24px 时仍能区分行为类型。
- 模型的主体、描边、阴影和高光符合本规范的明度层次。
- 动画没有改变逻辑坐标和命中判定。
- 特效有清晰的开始、命中、结束状态，不留下无法解释的残留光团。
- `node --check js/game.js` 通过，浏览器 error / warn 为 0，并在视觉测试台补充对应状态检查。
- 较大美术改动同步 `docs/需求方案.md`、`docs/更新日志.md` 和 README。
