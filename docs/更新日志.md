> ## 维护约定（改代码前先读）
>
> 1. **每次「较大改动」必须在本文件顶部追加一节，并同步更新 `docs/需求方案.md` 的对应章节**，两者缺一不可。
> 2. 什么算「较大改动」：新增/重做机制、新卡牌或新进化、新系统、成批数值调整、表现大改 —— 这类才新开一节。
>    小改动（增删某个选项、局部数值调整、文案修正、修错别字等）**直接并入最新一节**，不要每次改动都新开版本。
> 3. 每节写法：`## vX.Y · YYYY-MM-DD —— 一句话主题`，下面按 **新增 / 调整 / 修复** 列要点；
>    每条一句话说清「改了什么 + 为什么 / 效果」，涉及数值的直接写清 旧 → 新。
> 4. 版本号：机制重做、新系统、成批数值调整 → `+0.1`；纯数值微调 → 可用 `vX.Y.Z`。
>    `docs/需求方案.md` 的标题版本号要与本文件最新一节保持一致。
> 5. 提交前自查：`需求方案.md` 是否与本文件一致？本次改动有没有漏记？
>    数值尽量先在浏览器测试台实测再写进文档，不要写估算值。

## v1.26.2 · 2026-09-21 —— 首领不再「在原地打转」；冲锋指示带前段追踪、后段锁定

### 背景

两处首领表现被同时反馈为「在原地打转」，实测都成立：

1. **走位**：`moveBoss` 的径向修正是「出了 `orbitR ± 60` 的死区才给满速」的开关式 —— 只要距离落进死区就完全不修正，于是首领停在**死区边缘**（实测冲锋者 **206**、分裂者 **60**，目标分别是 150 / 110）。同时绕行方向每 2.5~5.5s 就翻转，而首领只有 28~40 移速（绕一圈要 20~75 秒），**一段弧都走不完就折返**：四种首领 20 秒的**净**绕行角度分别是 -25° / -34° / -5° / -47°，等于原地抖。
2. **冲锋指示带**：蓄力 1 秒里首领完全不移动，而 `aimBossCharge` 以 6 rad/s 全程把方向转向玩家 —— 实测**每帧瞄准误差恒为 0°**，指示带永远精确指着玩家：既读不出该往哪躲（横着跑它也跟着转），视觉上又是「站着原地转圈」。

检查其他首领时又发现一个连带 bug：**分裂者的突进撕咬从来没触发过**。它「已贴脸就不突进」的阈值是 `e.r + 70 = 116`，而它自己就停在 `orbitR = 110` —— 永远落在阈值内，每次都被判成「贴脸」，招牌技能成了死代码。

### 修复

- **走位收敛**：径向修正改为**按偏差比例**给（`radial = clamp((d - orbitR) / BOSS_MOVE.band, -1, 1)`，`band` 60 → 45），越接近目标距离修正越小，首领真正停在 `orbitR` 上；绕行方向翻转间隔 `flipMin / flipMax` **2.5~5.5s → 6~11s**，让它至少走完一段看得出来的弧再折返。
- **蓄力瞄准前段追踪、后段锁定**：新增 `BOSS_SKILL.trackFrac = 0.4`，蓄力前 40% 仍按 6 rad/s 转向玩家（冲刺不至于白放），之后方向锁死、指示带跟着停住。用**比例**而不是固定秒数：二阶段连冲的前摇只有 0.45s，固定 0.4s 等于几乎不锁定。锁定后「指示带 = 真实落点」这条不变（冲刺复用的是同一个方向向量）。
- **分裂者撕咬阈值**：`e.r + 70`（116）→ `e.r + S.soldierR + CONTACT_PAD`（66），即「只有真的贴到身上（进入接触伤害范围）才不突进」。

### 验证

- `node --check js/game.js` 通过；浏览器实测 0 报错。
- **稳定距离**（玩家静止、各跑 20~30 秒）：冲锋者 206 → **159/150**（冲刺落地后会短暂贴近，属正常）、弹幕者 293 → **296**、召唤者 300 → **300**、分裂者 60 → **109**（目标 110）。
- **绕行**（20 秒绝对绕行角度）：冲锋者 **212°**、弹幕者 **47°**、召唤者 **76°**、分裂者 **385°**（旧版净绕行只有个位数角度，走一小段就折返）。
- **蓄力锁定**：给首领喂 1.0s / 0.45s 两种前摇，实测锁定段分别是 **0.58s / 0.27s**（≈ 后 60%），锁定期间玩家绕圈跑、方向一动不动；冲刺方向与锁定方向完全一致。
- **`landingErr` 仍为 0**：把玩家挪出冲刺路径后实测指示带长度 **369.6** = 实际位移 **369.6**（旧记录里的「落点短了」是首领撞在玩家身上被挡住的正常碰撞）。
- **分裂者撕咬**：30 秒内触发 **96 帧**（≈3.7 次，旧版 0 次）；二阶段咬 136 帧、裂生精英 4 只（自身裂生上限 2 + 狂暴再裂 2），与设计一致。
- **其他首领复核**：弹幕者一阶段技能号 0~3、二阶段 0~4（含「交叉双螺旋」434 帧、同屏子弹峰值 145）；召唤者召唤阵落成后小怪带盾（grunt 18 / fast 13，均不超各自最大生命 50%）；冲锋者二阶段连冲 `combo` 达 2（三段）、30 秒 11 次冲刺。
- **回归**：`tests/visual-smoke.html` 新增 4 项断言（走位收敛到 `orbitR` / 蓄力前段仍在追踪 / 窗口后锁定 / 分裂者会突进撕咬），**57 项检查全部通过**。

## v1.26.1 · 2026-09-21 —— 首领伤害整体下调约 20%（玩家初始队伍血池只有 100）

### 背景

玩家开局只有 **1 名小兵 × 100 血 = 100 血池**，而 V1.25 把首领伤害推到「接触 38 + 冲刺 80」：一发冲刺加一次接触就是 **118**，直接超过血池上限，等于**一次失误就被带走**，首领战的容错是 0。这次只调数值、不动行为，把首领的单次爆发压到血池以内。

### 调整

- **首领伤害整体下调约 20%**（`WEAPON_DEFS.boss.dmg` / `BOSS_SKILL` / `BOSS_SHOCK` / `BOSS_BITE`，只改基础数值，难度倍率 / 护甲 / 护盾 / 闪避的结算链路完全不变）：
  - 接触伤害 `dmg` **38 → 30**；
  - 冲锋者冲刺 `BOSS_SKILL.damage` **80 → 65**，落点震波 `BOSS_SHOCK.dmg` **25 → 20**；
  - 分裂者突进撕咬 `BOSS_BITE.dmg` **26 → 20**。
- 弹幕者的弹幕子弹（7~11 / 发）**不动** —— 它是持续消耗型伤害，本来就不是「一发带走」的来源。

### 验证

- `node --check js/game.js` 通过；浏览器实测控制台 **0 报错**、无 NaN。
- 逐项实测掉血与配置一致：**冲刺 65 / 接触 30 / 震波 20 / 咬 20**（血池 100）。
- 关键组合：**冲刺 65 + 一次接触 30 = 95 < 100** —— 旧值 **80 + 38 = 118 ≥ 100** 会被一发带走，现在同样的连招打完还剩 5 点，玩家有一次反应机会。
- 贴身接触的持续 DPS 基本持平（新 **150** vs 旧 **153.33**）：本次降幅体现在「单次爆发不再秒杀」，而不是削弱首领的持续压迫。

## v1.26 · 2026-09-21 —— 新增「局内调试面板」（开发者模式），把测试动作做成按钮

### 背景

以前测数值、测卡、测首领行为都得开浏览器控制台手敲 `startGame()` / `addSummon()` / `update(1/60)` 这类语句：门槛高、不可复现，也没法边打边看。而现有的开发者面板只能改**局外存档**（金币 / 宠物 / 存档导入导出），对局内什么都动不了。这次把日常测试动作全部做成按钮。

### 新增

- **局内调试面板**（`#dev-hud`，仅 `meta.devMode === true` 时可见）：对局 / 暂停中按 `` ` `` 或 `F1` 开关，右上角的调试入口按钮也能点开。共四页：
  - **波次**：当前波次 + 计时读数（每次刷新 5 次/秒）、**±1 波**、**跳到指定波**、**立刻结束本波**（第 5 / 10 波倍数会照常刷精英 / 首领）、**清空场上敌人**（同时解除首领竞技场）、**冻结波次计时**、**刷一群精英**、**立刻出 Boss**。
  - **刷怪**：种类下拉（4 种首领 / 精英（随机词缀、无词缀）/ 自爆怪 / 猎人 / 治疗兵 / 护盾兵 / 召唤兵 / 树怪 / 普通·快速·远程怪 / 木桶·箱子·石柱·树木）、数量 **1~40**、位置（玩家附近 / 屏幕中心 / 屏幕边外 / 场上随机）。两个关键开关：
    - **站桩**：不移动、不吃击退、不被小怪推挤、不被障碍物推动（固定的靶子）；
    - **停手**：不造成任何伤害 —— 子弹、接触伤害、自爆、首领技能与弹幕全部停掉（首领只保留走位）。
    - 两个开关可**一键套用到全场**（`全场切换站桩 / 全场切换停手`）。
  - **卡牌**：把**全部 83 张卡**列出来（升级卡 + 8 张进化 + 10 张首领奖励），**默认忽略前置** —— 未携带的武器、没有的元素 / 召唤物、没点过的进阶链都能直接拿（缺「容器」时自动补上对应武器 / 召唤物）；按 **8 个分类**（全部 / 生存功能 / 武器 / 元素 / 召唤 / 宠物 / 进化 / 首领奖励）筛选 + 关键词搜索，点一下即生效，已获得的卡标「已选」。「只看当前可选」可切回严格模式。
  - **玩家 / 时间**：无敌、**秒杀**（一击必杀，连盾一起打穿）、士兵 ±1、回满血、直接升级、经验 +200、重抽 +3、**游戏速度 x0.25 ~ x4**、暂停 / 继续、**单步 1 帧**，以及一个**实时读数浮层**（fps · 速度 / 波次 · 时长 / 敌 · 子弹 · 召唤 · 掉落 / 血量 · 等级 · Boss 状态）。
- **升级池的调试开关** `devForcePool` + `poolGate()`：把池内所有「前置 / 上限 / 已选过 / 二选一」判定统一包一层，调试时全部放行。关掉时逐条短路回原逻辑，正常抽卡完全不受影响。
- 敌人实体新增两个调试标记 `devStatic` / `devPeaceful`（只在通过调试面板刷怪时才会挂上）。

### 调整

- 所有开关**默认都不影响玩法**：`devSpeed = 1`，无敌 / 秒杀 / 冻结波次默认关闭，站桩 / 停手只作用于面板刷出的怪；

- 入口按钮与信息浮层只在**对局 / 暂停**中显示，回主菜单或结算自动收起；面板展开时信息浮层自动让到左下角，互不遮挡。

### 验证

- `node --check js/game.js` 通过；浏览器实测控制台 **0 报错**、无 NaN、无越界（20s 压测：站桩首领 + 6 只快速怪 + 精英 + 石柱）。
- **热键与显隐**：关掉 `meta.devMode` 后入口按钮自动隐藏且面板自动收起（首版 `` ` `` / `F1` 的开关其实关不掉，见下方「修复」）。
- **波次**：跳波 9 → 「立刻结束本波」进入第 10 波并刷出首领（`bossArena` 同步开启）；冻结计时后 25s 仍停在第 3 波；清空场上敌人后 `bossArena = null`、`enemies.length = 0`。

## v1.25.1 · 2026-09-21 —— 首领取消滑步与两种「纯挪位置」位移；冲锋蓄力预警条 = 真实落点

### 背景

V1.25 给首领加的**滑步闪避**表现很怪：首领的技能都有明确前摇，「读前摇 → 走位躲开」是玩家唯一的博弈点，而它横着滑开一下会让前摇读不清、动作突兀。同一道理，**弹幕者的后跃 180** 与**召唤者的贴身闪现 340** 这两种「纯挪位置、无伤害」的位移也是「毫无征兆地换位置」，同样读不出、表现突兀 —— 这三样一并停用。另外实测发现**冲锋者的蓄力指示带指向和实际冲刺落点对不上**（贴边冲刺时最多差 **370** 单位），玩家照着指示躲反而被撞中。

### 调整

- **首领滑步闪避全部取消**：删掉 `tryBossDodge` / `applyBossDodge` 两个函数、`BOSS_DODGE` 常量组、`dodgeT / dodgeCd / dodgeDirX / dodgeDirY` 四个实体字段，以及 `updateBoss` 里的滑步分支与 CD 递减。四种首领一视同仁 —— 机动性只保留**轨道走位**与**带伤害的爆发位移**（冲锋者冲刺 / 分裂者突进）。状态机优先级随之简化为**位移中 > 蓄力 > 施法中 > 常规走位 + 技能模组**。
- **弹幕者「后跃 180」与召唤者「闪现 340」注释停用**（两次「纯挪位置、无伤害」的位移，代码保留以便恢复）：
  - `updateBarrageBoss` 末尾的「放完瞬发技、玩家贴太近就后跃」整块注释；`updateSummonerBoss` 开头的「贴身 150 内闪现到 340 外」整块注释；
  - 配套的 `bossLeap()` 函数、`BOSS_LEAP` / `BOSS_BLINK` 常量组、`blinkCd` 字段与 CD 递减一并注释（均带 `V1.25.1 停用` 标记，恢复时按标记反注释即可）；
  - 保留**冲锋者蓄力冲刺**与**分裂者突进撕咬** —— 这两个是带伤害、有前摇/有表现的招牌技能，不属于「纯挪位置」。

### 修复

- **冲锋蓄力预警条与落点对齐**（三处根因一并修掉，实测 `landingErr = 0`）：
  1. **蓄力期间持续瞄准**（新增 `aimBossCharge`，`aimRate = 6 rad/s`）：旧版在画完指示带之后才重新朝目标，方向被冻结；现在蓄力全程按该速率把 `skillDirX/Y` 转向玩家，而指示带与冲刺**共用同一个方向向量**，指示带指哪儿就冲哪儿。
  2. **位移帧精确结算**：旧版每帧整走 `速度 × dt`，末帧多走一帧余量（残留 **11.7** 单位）；现在 `stepT = min(dt, dashT)`，末帧只走剩余时间。
  3. **指示带长度改用 `bossDashReach`**：等于这次冲刺真实能走的距离（撞世界边界会缩短），箭头尖端画在哪儿、首领就停在哪儿。同时拆出 `clampBossWorld`（仅世界边界）供位移使用 —— 旧版位移吃的是「场地 + 220」软限制，会被提前顶停，而预警条仍按满距离画（贴边实测差 **370.8**）。

### 验证

## v1.20 · 2026-09-21 —— 允许首领碾碎挡路的建筑：不再「只有冲刺才能脱身」

### 背景

首领体型大（`r = 40`）、走位全由 AI 驱动，一旦抵住木桶 / 箱子 / 石柱就会被障碍物推出逻辑顶在原地，只能等它自己触发冲刺才挪开——打起来会出现「首领一直抵着柱子不动」的观感问题。

### 新增

- **首领碾压 `crushObstaclesByBosses(dt)`**：首领（含冲刺途中）与障碍物接触时分别处理——

## v1.19 · 2026-09-20 —— 闪电重做：触发判定改「窗口制」（硬间隔 0.35s → 0.30s），并移除全部「闪电触发概率」类选项

### 背景

**其一（窗口制）**：想「把落雷频率略微调高一点」，但改 `LIGHTNING_MIN_INTERVAL` 完全没反应。扫参后发现**旧机制下这个数字只有两档有效**：

| 硬间隔 | 机枪满层实测 |
|---|---|
| 0.40 | 1.82 次/秒 |
| 0.35 | 2.72 次/秒 |
| **0.30** | **2.72 次/秒** |
| 0.25 | 2.72 次/秒 |
| 0.20 | 2.72 次/秒 |
| 0.175 | 5.43 次/秒 |

原因是旧的「命中时 roll + `lightningCdT` 拦截」：判定机会只在**子弹命中那一刻**产生，而机枪每 0.175s 才有一轮子弹，于是 cd 还没走完的那次机会被白白浪费，实际落雷间隔被量化成**开火间隔的整数倍**——硬间隔只要落在 `(0.175, 0.35]` 里，一律等效 0.35s。

**其二（移除概率类选项）**：闪电的触发概率走的是「**命中敌人时按概率触发**」，且「额外闪电」叠到 4 层就是 **100%** —— 所有「触发概率 +X%」的加成在满层构建下**本来就是空效果**（100% 之上无法再加），只会占据奖励格子、误导选卡。故整条线一并去除，概率只留一条来源。

### 调整

- **触发判定改为「窗口制」**：一次落雷之后的 `LIGHTNING_MIN_INTERVAL` 秒算一个窗口，窗口内只要有子弹命中过敌人（`lightningPending` 布尔标记）就在窗口结束时判定一次。于是 **落雷频率 = max(硬间隔, 武器开火间隔)**，可以连续调。
  - `rollLightningOnHit(v)` 只负责「记下这轮打到了人」，判定抽离到新的 `tryLightning()`；`updatePendingLightning()` 在窗口结束（`lightningCdT <= 0 && lightningPending`）时补一次判定。
  - 重置点（`restoreRun` / `reset`）补上 `lightningPending = false`。
- **硬性间隔 `LIGHTNING_MIN_INTERVAL` 0.35s → 0.30s**：现在这个数字是真起作用的——机枪满层 **2.72 → 3.15 次/秒（+16%）**。
- **删除首领奖励卡「闪电触发概率 +20%」**（`buff-lightning-chance`）：一次性奖励池 **6 → 5 张**。
- **删除进化「苍穹雷暴」的「触发概率 ×1.5」**：`evo-lightning` 去掉 `s.chanceMul` 赋值，`desc` 改为 `'雷电：额外闪电 +2、伤害 +30%'`（伤害 `dmgMul` 与 `chainLv` 不变）。
- **`lightningChance()` 简化**：只看「额外闪电」层数——`lv >= 4 ? 1 : LIGHTNING_BASE_CHANCE`，即 **0~3 层 50%、满 4 层 100%**，不再有任何可叠加的加成项。

- **副作用（由 V1.15 的补位规则兜底）**：一次性池只剩 5 张、面板最多 6 格，所以**从第 1 个首领起就会混进 1 张补位卡**，但不会出现空格子。
- 落雷延迟、伤害与「必须命中才触发」的前提都不变（`LIGHTNING_DELAY = 0.15s`）。

### 新增

## v1.9 · 2026-09-19 —— 伤害乘区下限统一 + Boss 「专精」路线取舍卡

### 调整

- **统一伤害乘区的下限层级**：下限改为**只作用在「加算区」这一层**（`dmgBase.X × max(下限, 1 + Σ加成)`），独立乘区（`w.dmgMul` / `s.dmgMul` / `pet.dmgMul`）一律只做纯乘、不再带下限。四路取值明确：子弹 / 召唤 / 宠物 0.3，元素 0（保留「可被归零」这一设计杠杆）。
  - 旧 → 新（`refreshSummonMul`）：`max(0.3, (1 + dmgAdd) × dmgMore)` → `(1 + dmgAdd) × dmgMore`。此前「数量 +1」类卡的 ×0.9 叠到 12 张（0.9¹² ≈ 0.282）就会触底失效、进化卡的 ×1.3~1.4 也被同一个下限截断，现在按原值生效（实测 12 张后 `dmgMul = 0.2824`，再乘进化 1.4 得 `0.3954`）。
  - 旧 → 新（`recalcDamage`）：`max(0.3, dmgBase.bullet × (1 + Σ子弹))` → `dmgBase.bullet × max(0.3, 1 + Σ子弹)`。此前局外装备（力量护符 ×1.15）会被极端减益一起压到 0.3，现在保留装备倍率（实测 1.15 × 0.3 = **0.345**，旧为 0.3）。
  - 宠物弹丸不再用 `max(1, stats.elementalDamage)` 兜底，改为直接吃 `stats.elementalDamage`，与元素线同规则。
  - `pet-dmg` 卡（`baseMul × max(0.3, 1 + dmgAdd)` → `baseMul × (1 + dmgAdd)`）与 `restoreRun`（召唤物 / 宠物乘区改为**无条件重算**，避免旧存档里带着旧下限的 `dmgMul` 卡住）同步跟上。

### 新增

- Boss 奖励新增一对**互斥的路线取舍卡**（参考 20 Minutes Till Dawn 的取舍型 Synergy：一次性、幅度写死、代价只扣一个固定百分比且之后仍可补回）：
  - **元素专精**：元素伤害 +50%、子弹伤害 -30%。
  - **实弹专精**：子弹伤害 +50%、元素伤害 -30%。
  - 两张幅度对称，均需有元素来源；带 `once: true`（拿过不再出现）与 `exclusive: 'dmg-route'`（同组已选则对方不再出现；同一波奖励里选走一张，会把另一张从当次候选一并撤出）。
  - 新增 `hasExclusivePicked(group)` 供 Boss 奖励去重使用。
- `pickBossReward` 改为选卡后过滤候选并重渲染，从而实现「同波二选一」。

### 修复

- 修复 **Boss 奖励可重复拿同一项**：此前不查 `appliedIds`，每波 Boss 都可能再拿到同一张 Buff。
- 修复 **「子弹 +50% / 元素归零」与「元素 +100% / 子弹 -50%」两张都拿会互相抵消**：两张都写在同一个加算区（`-1` 与 `+1` 相抵、`+0.5` 与 `-0.5` 相抵），结果玩家花两个奖励位拿到「双双归零」。改为互斥二选一后该状态不可能出现，顺序敏感问题也一并消失。
- 修复 **Boss 奖励卡文案歧义**：旧文案「已累积的元素加成清零」容易被读成「回到无加成」，而实现是伤害倍率归零；新文案直接写清增减幅度。

## v1.0 · 2026-09-17 —— 飞剑体系重做、镰刀「可攻可防」、武器调优

### 新增

- **飞剑 · 护身剑阵**：小队 80px 内出现敌人时，在外追击的剑立刻放弃远处目标回身护主（不打断正在进行的贯穿滑行），剑身外圈闪一圈蓝环。
- **飞剑 · 贯穿打击反馈**：命中留下沿剑身方向的细长白光 + 扩散冲击圈（0.2s 淡出），并触发 0.02s 顿帧（节流 0.25s）+ 轻微震屏。
- **镰刀 · 饮血 +10%**（最多 2 张）：镰刀造成伤害的 10% 回复队伍生命，作为「可攻可防」进化线的铺垫卡。

### 调整

- **飞剑：从「周期射出子弹」重做为常驻剑体**
  - 在视野内（300）的敌人之间穿梭贯穿；无敌人时**剑尖朝下绕角色环绕**（半径 48 · 2.0 rad/s，多柄按 2π/柄数 均匀分布）。
  - **惯性滑行**：贯穿后沿剑尖继续滑出 0.22s（保留 72%~100% 速度），滑出约 100px 再折返；折返时机按「剩余冷却刚好够冲回去」反推，保证每次贯穿都结算伤害、不空穿。
  - 基础值 15 伤害 / 1.1s → **9 伤害 / 0.6s**，飞行速度 380（原 430），索敌 300。
- **飞剑：多柄目标从「硬占位」改为「软避让 + 节奏错峰」**
  - 硬性「同一敌人只归一柄」会让剑在敌人少时干等；改为：索敌优先挑 0.35s 内没被任何飞剑穿过的敌人，多柄初始冷却按柄序等分错峰，敌人少时允许集火。
  - 实测：1 敌 3 剑 44.1 DPS（4.9 次/秒 = 冷却上限），5 敌围拢时每趟平均命中 1.56 只。
- **镰刀：修正几何，消除贴身盲区**
  - 环绕半径 70 → **52（固定）**、「变大」卡不再把环推远（只放大刀刃与判定 ×1.3）、判定半径 **24**、每敌受击冷却 0.25s → **0.16s**。
  - 原因：原设计下刀刃绕 70 环、每圈只扫到一次，贴身（<44px）与远距（>96px）都打不到，实测单刃单体只有 6 DPS。
  - 效果：有效范围变为约 14~90px，贴身 25px 从 **0 → 15.3 DPS**，环上 17.3 DPS，5 敌围拢 80.7 DPS。
- **进化 · 死神镰刀 改为「可攻可防」形态**
  - 前置：镰刀击退 + 变大为「**饮血 ≥1 张 + 阻挡子弹 ≥1 级**」；效果改为 数量 +2、伤害 +40%、**吸血 30%**、**子弹碰到刀刃即被斩落**（从 45% 概率改为确定性）。
- **散弹：弹丸更多、单发更弱、总伤害更高**
  - 3 发 × 8 伤害 → **5 发 × 6 伤害**（单轮 24 → 30）；新增 **110px 处收束射界**与弹丸横向错开 5px；整轮共用一次散布（0.5 → 0.28）。
  - 原因：弹丸原本平行错开射出，弹丸越多外侧越偏离，拿「弹丸 +5」卡后贴脸 DPS 反而从 25.8 掉到 22.2，与「弹丸更多 = 总伤害更高」相反。
  - 距离衰减 110→250（×1.4 / ×0.7）→ **110→170（×1.4 / ×0.35）**，保持近战定位。
  - 效果：贴脸 23.1 → **30.8**，远距 7.9 → 9.3；拿弹丸卡后贴脸 22.2 → **51.9**。
- **机枪伤害 6 → 7**（DPS 16.4 → 19.1），与其他三把武器收敛到 17~20 的区间。

### 修复

- 飞剑角度差取模在角度累积偏大时会算出超出 ±π 的差值，导致剑乱转；改用 `atan2(sin, cos)` 求最短夹角。
