> ## 维护约定（改代码前先读）
>
> 1. **每次「较大改动」必须在本文件顶部追加一节，并同步更新 `docs/需求方案.md` 的对应章节**，两者缺一不可。
> 2. 什么算「较大改动」：新增/重做机制、新卡牌或新进化、新系统、成批数值调整、表现大改 —— 这类才新开一节。
>    小改动（增删某个选项、局部数值调整、文案修正、修错别字等）**直接并入最新一节**，不要每次改动都新开版本。
> 3. 每节写法：`## vX.Y · YYYY-MM-DD —— 一句话主题`，下面按 **新增 / 调整 / 修复** 列要点；
>    每条一句话说清「改了什么 + 为什么 / 效果」，涉及数值的直接写清 旧 → 新。
> 4. 版本号：机制重做、新系统、成批数值调整 → `+0.1`；纯数值微调 → 可用 `vX.Y.Z`。
>    `docs/需求方案.md` 的标题版本号要与本文件最新一节保持一致。
> 5. 提交前自查：`需求方案.md` 是否与本文件一致？本次改动有没有漏记？
>    数值尽量先在浏览器测试台实测再写进文档，不要写估算值。

## v1.37 · 2026-09-25 —— 双人对战内核（第一批：能一起打 + 各自选卡）

> 背景：V1.36 把「合作房间」做成了能建房 / 邀请 / 加入的大厅，但两个人都点「准备」也只是大厅里的状态位。本版落地**对局同步的第一批**：房主权威 + 客机回放 + 跨玩家判定，以及**升级时两人各抽各的卡**。范围仍然只是「**能一起打**」—— 结算页 / 快照插值 / 打击反馈 / 双人难度放大 / 合作榜留给下一批（见第 12 节）。

### 新增

**A. 玩家槽位（`players[]` / `switchTo` / `withCtx`）**

- 世界从「一份全局战斗状态」改成 **`players[]` 槽位**：`squad / soldiers / squadHp / squadMaxHp / stats / weapons / summons / pet / skills / pickCount / routePicks / appliedIds / dmgBonus / dmgBase` 这批全局变量**始终代表「当前生效的玩家」**，靠 `switchTo(p)` 换人、`withCtx(p, fn)` 临时借用。
- 好处是**现有 40 多个战斗函数一行没改**：`updateSquad` / `updateWeapons` / `hitEnemy` / `damageSoldier` … 仍然读写那些全局名，「当前代表谁」由槽位决定。`captureCtx(p)` / `loadCtx(p)` 负责「全局 → 槽位」与「槽位 → 全局」的镜像。
- **单人局 `switchTo(P1)` 是空操作**（`players` 只有 P1）：零开销、零行为变化，原有的单人断言全数照过。
- `soldier.owner` 存的是**玩家 id（数字）而不是玩家对象引用** —— 引用会让 `soldiers ⇄ player` 成环，`saveRun()` 的 `JSON.stringify` 抛 `Converting circular structure to JSON` 后被 try/catch 吞掉、`meta.run` 静默置空（「返回主菜单后继续」失效）。回归台有断言守住这一条。

**B. 联机内核（房主权威 + 客机回放）**

- 传输层：Supabase Realtime 的 **public broadcast 频道** `room:<房间码>`，直接手写 Phoenix 裸 WebSocket 协议（`phx_join` → `phx_reply` → 心跳 → `broadcast`）。实测 **public 频道不走 `realtime.messages` 授权策略**，所以**零 DB 迁移**（沿用 0007 那张房间表即可）。
- **房主权威**：房主跑完整模拟（槽位 0 = 自己、槽位 1 = 客机），约 **18Hz**（`NET_SNAP_MS = 55`）广播世界快照。
- **客机不跑 `update()`**：只把移动意图上行（`in`，值变了才发，省流量），并按快照回放 `render()` —— 因为渲染层本来就**只读世界**（V1.32 的不变量），所以「把快照灌进全局 + `render()`」是安全的。
- `netConnect(code, role)` **必须等 `phx_join` 被服务端确认后才 resolve**：早于确认就发广播会被服务端**静默丢弃**（实测：房主的 `run:start` 就是这么丢的，很难查）。
- 开局消息**只带种子**（`seed` + `mode`），两边各自 `reset(seed)` 得到同一张地图 —— 把整张世界（障碍物 / 藤蔓 / 装饰）塞进消息里体积能到上百 KB。

**C. 跨玩家判定**

- 敌人索敌本来就是**小兵级**（`nearestSoldier`），现在**跨全部玩家**找最近的小兵；`forEachSoldierAll(fn)` 同理。
- 半径类判定统一走 `anySoldierIn(x, y, r)`：**逐个玩家用「那名玩家自己的」`bodyR()`**（读他自己的 `stats.bodyMul`）—— 所以「小小巨人 / 大大巨人」的碰撞体积在双人下各算各的。
- 替换了 7 处范围判定：自爆怪爆炸、首领冲锋撞击、首领震波、首王砸落、精英爆炸、敌弹命中、**敌人与小队站位分离**。
- `damageSoldier(s, dmg, cause)` 按 `s.owner` 切到该玩家的上下文再结算 —— **打客机的兵只扣客机的血池**，本机血池一点不动。
- 跨帧效果带 `owner`：子弹（`stampNewBullets` 按数组长度差给「本段新产生的」打戳）、延迟落雷、宠物持续技；`updateBullets` / `updatePetFx` 在对应玩家的上下文里推进。
- 全灭判据改成「**两名玩家都不剩小兵**才结算」（单人局等价于原来的判据）。

**D. 升级 · 各自选卡**

- **等级与经验共享**（谁捡到都算），但**候选各抽各的**：`beginLevelUp()` 用各自那份 `pickCount / routePicks / appliedIds` 建池（`rollPickFor(p)`），两人的卡池互不影响。
- **世界在所有人都选完之前保持冻结**；本机先选完会看到「已选好，等待队友…」占位，不会对着同一组卡重复点。
- 房主把**给客机抽好的候选**（`id` + 文案）发过去（客机不必为了显示卡片重建一套卡池），客机选完回 `pick:choose`，**由房主在客机的上下文里落地** —— 权威始终在房主手上。
- `applyUpgrade(id)` 仍是唯一入口（数字键 1~6 / 卡片点击 / 测试台都走它）；**候选面板与待选槽位共用同一条数组引用**（`setLocalCards`），否则重掷之后会按旧 id 找不到卡（选了等于没选）。

**E. 收场链路（结算 · 中途退出 · 再开一局）**

- **通道的存活周期改成「在房间里」，不是「这一局」**：一局打完后双方都还在房间，房主再点一次「开始双人对战」就能直接开新的一局，不必重新进房 / 重新邀请。
- **房主收场时广播结果**（`run:end { won, wave, kills, level, time, coins, cause, peerCause }`）→ **客机也能看到结算页**了。此前客机只会**永远停在冻结的战场上**（房主那边 `gameOver` 之后 `isLive()` 变假、快照停发，客机却收不到任何收场消息，也没有结算页）。
- **中途退出**（暂停里「返回主菜单 / 新游戏」、结算页的「回到大厅」）统一走 `netLeaveMatch()`：先广播 `run:end { left: true }`，再退回大厅。
- **联机局的结算页只留一个出口「回到大厅」**：「再来一局」会开出一局单人、把队友晾在大厅，所以隐藏掉。
- **联机局不再调 `saveRun()`**（对局快照只保存「当前生效玩家」那套上下文，双人局本来就不能续玩），暂停里的「返回主菜单」改成「通知队友 + 回大厅」。
- 看结算页时对方收场只**提示**、不把结算页收走（`netBackToLobby(keepResult)`）；退回大厅会把槽位还原成单人（`players = [P1]`、`P1.id = 0`、清待选）。

**F. 打击反馈同步（伤害数字 · 浮动文字 · 震屏）**

- 房主把 `spawnDamageNumber` / `spawnFloatText` 产生的条目攒进队列，随快照节拍**额外发一条** `fx { shake, f }`（纯表现、**可丢**，一次最多 12 条；没有反馈也没震动就不发）。客机的 `netGuestFx()` 把它们摆进自己的 `damageNumbers` / `shake` —— 这两个本来就是渲染层自己的数据（`render()` 里自行推进），与「灌世界 + `render()`」是同一套做法。
- 效果：**客机打怪不再只是「怪默默掉血」**。此前客机没有任何伤害数字、浮动提示与震屏（那些全在房主的模拟里产生）。仍没同步的是**顿帧**（`hitStop`，一次几十毫秒的冻结）与**音效** —— 音效是逻辑层在命中时触发的，客机不跑逻辑，所以客机听不到打击音。

### 调整

- **输入同源**：键盘与虚拟摇杆合成的移动意图抽成 `joyVec()`，`updateSquad` 与联机上行共用它。
- **结算页渲染抽成 `renderGameOverPanel(res)`**：房主侧传实测数据、客机侧传房主下发的数据（`fromNet: true` → 不显示「本局学到的机制」、金币那一行改成「由房主那一侧结算」）。
- **把剩下几个「其实该按玩家分」的全局补进槽位**：`lightningCdT` / `lightningPending`（雷电那条线的硬性触发间隔）、`hurtBy` / `lastHurt`（受伤来源统计）、`petRunExp`（宠物熟练度）。它们原本是全局单份，双人下会互相干扰 —— **客机打出的雷会把房主的雷卡在冷却里**、**两人的受伤混进同一份阵亡原因**（房主的结算页可能写出别人的死因）。顺带把 `makePlayer` 的 `appliedIds` 默认值从 `[]` 改成 `new Set()`（此前只有 `coopSpawnLocalAlly` 手工纠正过）。
- **客机的阵亡原因改成「它自己那一份」**：房主本来就替客机记着（扣血按 `owner` 分账），现在随 `run:end` 一起下发（`peerCause`），客机结算页显示的就不再是房主的死因了。
- **`update()` 拆成两个相位**：`updatePlayerCombat(p, dt)`（移动 / 护盾 / 技能 / 开火）与 `updatePlayerCompanions(p, dt)`（召唤物 / 宠物），刻意夹住 `updatePendingLightning` —— 单人局的执行顺序与改动前完全一致。
- **镜头**：`updateSquad` 不再自己调 `updateCamera()`，改由 `update()` 统一算（双人下各自独立镜头）。
- **渲染**：`drawSoldiers()` 外面包一层 `drawAllPlayers()`，逐玩家切上下文各画一次（单人局直接走原路径）。
- **状态机**：`upgrade` / `bossreward` 允许转移到 `menu` —— 队友断线时房主要能从选卡面板里退出来，不再卡死。
- **联机中断的收场**：`netAbort()` 把槽位还原成单人并清掉待选，避免残留的双人槽位被「继续游戏」带进单人局。
- **本地开发服务器**：`/api/leaderboard` 现在会下发 `realtime` 连接信息（配好 `SUPABASE_URL` + `SUPABASE_ANON_KEY` 即可），此前**硬编码 `null`**，本地根本没法联机调试。
- **读档一律回到单人槽位**（`restoreRun`）：对局快照只保存「当前生效玩家」那套上下文，双人局本来就不能续玩。

### 修复

- **客机从来没有建立过连接**：`netConnect` 此前只在房主侧（`netHostBegin`）调用过，客机的输入**全部发不出去**（`netSend` 直接返回 false）。现在建房 / 进房时就把通道接好，离开房间时关掉。
- **开局后好友面板不收起**，盖住战场 —— 开局两边都先 `closeFriends()`。
- 插入联机代码时误删了 `btn-friends` 的事件绑定（好友入口失效），已补回。
- **`phx_join` 的回执被写死按 `ref === '1'` 认，导致「第二次及以后的连接连不上」**：`netSendRaw` 用 `String(netRef++)` 生成 ref，而 `netRef` 是全局自增、`netClose()` 不清零 —— 只有**页面加载后的第一次连接**才恰好是 `ref = '1'`；只要之前发过任何一条广播（或**退出房间后再建一次房 / 客机重新进房**），回执就对不上，于是卡满 `NET_JOIN_TIMEOUT`（9 秒）才失败，界面只留一句「联机通道未响应（可能是网络或 Realtime 配置问题）」—— **看起来像网络问题，实际是本地对不上号**。修法：`netSendRaw()` 返回本次消息用的 ref，`netConnect` 把它记进 `netJoinRef` 并只认这个 ref 的回执。回归台用一个**假 WebSocket** 连续握手两次守住它。

## v1.36 · 2026-09-24 —— 合作房间（第一批：把「UI 占位」做成能真的用）

> 背景：好友面板底部那块「合作房间」从 V1.34 起就只有 DOM 与样式、**没有任何事件处理器** —— 点「生成房间码」当然不会有反应，多人玩法本身也不存在。本版把它做成**能真的用的一小套房间系统**（第一批），**双人对局的同步内核仍留到下一版**。

### 新增

**A. 房间系统（建房 / 邀请 / 加入 / 就位）**

- **生成房间码**：6 位，字母表刻意去掉 `I / O / 0 / 1`（`ABCDEFGHJKLMNPQRSTUVWXYZ23456789`，32⁶ ≈ 10 亿种）—— 好友之间靠嘴念、靠手打都不会认错。
- **复制邀请**：复制 `https://<站点>/?room=<房间码>`；对方点开这个链接会自动打开好友面板、把房间码填进输入框（`coopHandleUrl()`，**整次会话只处理一次**，不会每次回主页都弹面板）。浏览器没有剪贴板 API 或写入失败时，退化为提示手工转发房间码。
- **输入房间码加入**：`#coop-input` + 「加入房间」，回车也能提交；前端统一「去空白 + 大写」再校验（`normCoopCode()` / `coopCodeOk()`）。
- **房间面板**（进房后取代建房区）：房间码金色大字 + 「复制邀请」+ **两个席位**（头像 + 名字 + 「房主 · 已准备 / 未准备」，空席位显示「等待好友加入…」）+ 「准备 / 取消准备」+ 「离开房间」。
- **在好友列表里直接邀请**：在房间里且**还有空位**时，好友行多一个「邀请进房」按钮（房间满了就不再显示）。
- **收到的邀请**排在面板最上方：`【头像】<名字> 邀请你加入房间 <房间码>` + 「加入 / 忽略」（忽略是服务端删掉这条邀请，不是本地隐藏）。
- 面板上一句如实说明：「房间已可创建、邀请与加入；双人对局同步开发中，暂时只能在房间里就位。」

**B. 服务端（DB → api → server.js 三层同步）**

### 修复

- **落雷特效的负半径崩溃（`IndexSizeError`，会打断整帧渲染）**：根因是 `loop()` 的单帧 `dt` **可能为负** —— `startGame` / `resumeGame` 会把 `last` 设为 `performance.now()`，而 rAF 回调拿到的是**本帧开始**的时间戳；若这一帧中途跑了长任务（测试台的同步检查、卡顿），`now < last`，`raw` 变负。负 dt 会让所有 `x -= dt` 的计时器**倒着走**，实测落雷 `life` 反涨到 `maxLife` 的 1.4 倍，算出**负半径**的地面环。修法：把帧间隔换算抽成 `frameDt(raw) = clamp(raw/1000, 0, 0.05)`，并把 `drawLightningBolts()` 的进度 `k` 钳到 `[0,1]` 作二次防线。
- **引导提示条的 `.hidden` 失效**：`.guide-tip` 自带 `display: flex`，与 `.hidden` 同优先级且写在后面，会把 `.hidden` 压掉 —— 导致暂停 / 升级面板上仍浮着一条引导。加 `.guide-tip.hidden { display: none }` 修掉。
- **好友面板里的死引用**：`#btn-friends-add` / `#friend-rail-list` 删除后 JS 仍在绑定，会抛 `TypeError`；`renderFriendRail()` 改名 `renderFriendBadge()`。
- **`petAnvilInner` 尾部残留旧代码**：页面重写后仍是 `wrap.innerHTML = html; box.appendChild(wrap)`，而 `wrap` / `box` 已不存在 —— 改成 `return html`。
- **装备页左侧栏的事件委托**引用已删除的 `#equip-slots`，重写为 `#equip-body` / `#pet-body` 上的 `[data-nav]` 委托（`slot` / `list` / `anvil` / `egg` / `pet`）。
- **横屏下「切换攻击目标」按钮被调试面板盖住（需求 3 的遗留）**：竖屏里按钮在右上角（`right: 14px`）、调试面板贴左下，两者不冲突；但**横屏**下面板改成贴右侧（`right: 8px`、宽 360px），正好压在按钮上（面板 `z-index: 25` > 按钮 `5`）。现在 `setDevHud()` 会给 `#stage` 打一个 `dev-open` 类，横屏下按钮自动让到左上（`#stage.landscape.dev-open .ingame-btn.aim-btn`），并加了一条断言：横屏 + 面板展开时两者的矩形不相交。
- **本地开发服务器不发 `Cache-Control`，浏览器启发式缓存会喂旧的 JS**：`server.js` 的静态分支只写了 `Content-Type`，于是浏览器按启发式规则缓存 `js/game.js` 与 `tests/visual-smoke.js`，**改完代码刷新页面仍在跑旧脚本** —— 表现为回归台打印的断言文案是上一版的、实测数值也是旧的（排查过程中一度误读到「首次升级 10.2 秒」这个过期数据，清缓存后复测为 19.7 ~ 21.4 秒）。现在静态资源统一 `Cache-Control: no-store`。
- **龙蛋「喷火」画在玩家身上**：`castPetSkill('breath')` 建特效时带的是 `follow: true`，而 `updatePetFx()` 里 `follow` 会把原点**每帧拉回 `squad` 中心** —— 于是扇形一直从玩家身上喷出来（`x: p.x, y: p.y` 那两行等于白写）。改成 `onPet: true`，`updatePetFx()` 里走 `petPos()`；同时把表现从「一整块静态扇形」换成**三层火焰 + 火舌 + 嘴部高光**（原点沿朝向外推 13px，从宠物嘴边喷出）。

## v1.34 · 2026-09-24 —— 好友与头像（新系统）：常驻好友栏 + 复用怪物模型做头像

### 新增

- **好友系统（真实好友关系，不是本地假数据）**。关系存在服务端，前端只负责渲染与发起操作：

  | 层 | 文件 | 内容 |
  |---|---|---|
  | 数据表 | `supabase/migrations/0005_friends.sql` | `friendships(requester, addressee, status)`，`status ∈ 'pending' \| 'accepted'`；`users` 加 `avatar jsonb` 列 |

## v1.33 · 2026-09-23 —— 四线「专精」卡（火焰 / 雷电 / 飞剑 / 镰刀）+ 牛来造型按原片校正

### 新增

- **四条「专精」链（各 3 段，数值为累计）**。与已有的「质变链」（割裂 / 剑印 / 冻伤，靠**概率**触发）分工明确：专精是**确定的数值成长**，而且补的是**固定伤害** —— 在这之前全游戏只有「基础值 × 倍率」，这是第一处「固定值直接加到基础值上」（加完再吃该线原有乘区，所以中期不会失效）。

  | 专精 | 出现门槛 | 三段数值（累计） | 生效位置 |
  |---|---|---|---|
  | **火焰专精** | 先有「火焰附魔」**或**带火系宠物 | 火焰伤害 **+3 / +6 / +12**（固定值）、点燃时间 **+0.3 / +0.8 / +1.5s** | `stats.fireFlat` / `fireBurnTime` → `applyBurn()` 的**基础值** |
  | **闪电专精** | 已解锁雷电 | 雷击**获得范围伤害**：半径 **90 / 130 / 180**、范围伤害 = 本次雷击的 **30% / 45% / 60%**；闪电伤害 **+10% / +20% / +35%** | `stats.lightningSplashR/Pct` → `lightningSplash()`；`lightningMastery` → `triggerLightning()` |
  | **飞剑专精** | 已召唤飞剑 | 飞剑伤害 **+2 / +5 / +9**（固定值）、**命中冷却 -8% / -15% / -25%** | `stats.swordFlat` / `swordHitCdMul` → `updateSword()` |
  | **镰刀专精** | 已召唤镰刀 | 镰刀伤害 **+2 / +5 / +9**（固定值）、**命中冷却 -8% / -15% / -25%** | `stats.scytheFlat` / `scytheHitCdMul` → `updateScythe()` |

  - **「卡面显示的是选完这次之后的累计值」**：第 1 张写 `+3`、第 2 张写 `+6`、第 3 张写 `+12`（不是增量 `+3 / +3 / +6`），`desc` 在 `buildUpgradePool()` 每次开面时按当前层数现算。
  - **半径 90 / 130 / 180 的取值依据**：对齐局内既有范围刻度 —— 雷暴单道雷 **80**、火球落点 **90**、熔岩 **95**、冰霜领域 **150**、霜冻新星 **180**。第 1 段（90）是「比一个落雷点略大」，满段（180）正好落在「霜冻新星」这一档，**不会变成清屏**。
  - **范围伤害走 `hitEnemy()`**（吃易伤 / 剑印 / 护盾 / 吸血一整套），不像落雷直击那样裸减血；**没点专精时半径 0 → 直接 return**，行为与 V1.33 之前完全一致。落雷还会多画一圈**范围圈**（`spawnLightningBolt` 新增 `radius` 参数）。
  - 四张卡**都不带 `route`**：不计入进化门槛的 `routePicks`，避免这 4 条线因为多了 3 张卡而提前进化。
  - 火焰专精**不会凭空挂点燃**（`applyBurn()` 在 `burnDps <= 0` 时直接返回），必须先有火焰来源。

## v1.32 · 2026-09-23 —— 第二阶段架构：双模式 + 存档版本与迁移 + 三条随机流 + 显式状态机（另含：牛来 / 武器模型重做、宠物元素线协同）

### 背景

第一阶段（V1.31）16 项需求落地后，第二阶段这 8 项都是「打地基」的事：双模式需要一个明确的结算条件、随机要可复现、存档要能换代、状态要能一眼看清。本版不开新玩法，只把这四件事做扎实，并顺手在单文件里立好四条模块边界，为后面「逐步拆文件」做准备。

### 新增

- **两种基础模式（`GAME_MODES`）**：

  | 模式 | 节奏 | 结算 | 解锁 |
  |---|---|---|---|
  | **标准** | 固定 **20 波**，首领波冻结计时，一局实际 **15~20 分钟** | 打完第 20 波即**通关结算**（波次推进到 21 的那一刻） | 默认开放 |
  | **无尽** | 没有波数上限，首领按 10 波节奏无限轮换 | 打到阵亡 | **标准模式通关后开放** |

  主页加入模式选择卡（选出战模式，写进存档），局内 HUD 在标准模式显示 `第 07/20 波` 进度、无尽模式标「无尽」，暂停摘要与结算面板也会带模式信息。通关结算走独立文案（`通关！` + 「无尽模式已开放」提示），成绩按**实际打完的 20 波**上报，不会把推进到 21 的那一波白算给排行榜。

- **存档结构版本与迁移流程**：存档新增 `schemaVersion`（当前 **`META_SCHEMA = 2`**），读档统一走 `migrateMeta()`：
  **① 校验 → ② 按版本逐步跑 `META_MIGRATIONS`（每步只负责「从上一版升到本版」）→ ③ 补齐字段（`normalizeMeta`）→ ④ 再校验一次并盖上当前版本号**。
  换结构时只要 `META_SCHEMA + 1` 并补一步迁移；**没有版本号的老存档按 v1 处理，会自动依次跑完所有升级步骤**，玩家不需要做任何事（v1 → v2 这一步给旧对局快照补上了随机流字段与「有护盾时受伤」字段）。
- **存档校验**：`validateMeta()` 分两档 —— 读档第一道门只查「致命」问题（非对象、关键字段类型错），迁移后再跑一次**严格校验**（字段齐全、数值合法），严格档**只告警不丢档**。来自「未来版本」的存档、以及结构不合法的手改档一律拒绝。
- **坏档备份 / 写入失败回滚**：
  - 每次保存前把**上一份好档**留成备份（`fury_meta_<user>__backup`）；解析或校验不过的存档把**原始内容另存备查**（`__broken`）且不覆盖备份；
  - 本机镜像改**原子写**：先写临时键 → 回读校验 → 通过才替换主键，失败就把临时键清掉、**主键保持上一份好档**（不会留下半截存档），并明确提示「本次进度没有保存」；
  - 开发者模式新增「**恢复上次备份**」按钮（并把「结构 v2 / 有备份 / 有坏档备查」显示在存档信息里）。
- **三条随机流（`rngWorld` / `rngCombat` / `rngFx`）**：一条流 = 一条可复现的 mulberry32 序列，彼此**互不干扰**：
  - **world**：地图 / 障碍物 / 装饰 / 藤蔓 + **刷怪**（位置、种类、精英词缀、首领种类、走位初始朝向）；
  - **combat**：命中判定与概率触发（点燃 / 减速 / 冻结 / 麻痹 / 分裂 / 闪避 / 格挡）、AI 技能编排、抽卡与掉落；
  - **fx**：纯表现（粒子、屏幕抖动、闪电分叉形状、音效噪声）—— 整条跳过也不影响战斗结果。
  全文件 **112 处 `Math.random()` 按语义分流了 105 处**（剩下 7 处是局外养成：开蛋、装备洗练、宠物词条，以及一句注释与种子默认值）；局外养成**不进这三条流**。
- **随机种子写进 `meta.run`**：对局快照带 `seed` + `rngCounts`（三条流已取用的次数），**同一种子复现同一张地图与同一套战斗判定**；读档时把三条流快进回同一位置（旧快照没有种子则记 `null`、保持当前流，不假装可复现）。`reset(seed)` 可指定种子（调试 / 测试用），不传就每局重掷。
- **显式状态机（`STATE_DEFS` / `setState`）**：状态、它占用的遮罩、世界是否推进、局内按钮是否显示，全部写在一张表里，所有切换统一走 `setState()`：
  `menu / playing / paused / upgrade / bossreward / merchant / gameover`（**merchant 为预留状态**，商人玩法尚未接入，遮罩缺失时静默跳过）。`isLive()` 成为「世界是否推进」的唯一判据，`update()` 及各处的 `state === 'playing'` 判断改用它。非法转移只在控制台告警、**不硬拦截**（避免某条正常流程被表漏掉后直接卡死）。
- **模块边界（单文件内先立界，暂不拆文件）**：`js/game.js` 顶部新增四层清单 —— **数据 DATA / 逻辑 LOGIC / 渲染 RENDER / UI VIEW**，并写成**可验证的不变量**：
  - 渲染层**只读世界**：`render()` / `draw*` 不改动实体与对局数据，也**不消耗 world / combat 随机流**（表现自己的随机走 `fxRng`），保证画面设置不会影响同一局的结果；
  - UI 层只改 DOM 与发起动作；逻辑层不碰 DOM（唯一例外是状态机的遮罩显隐）。
- **宠物 × 元素线的协同（需求 8）**：让**雷电虫 / 冰冻精灵**吃到「自己那条元素线」的加成。逐条盘点后确认**只有两处是真空白** —— 元素伤害乘区、减速 / 冻结的施加通道、「**冻伤**」（被减速 → 概率冰冻 + 扣当前生命%）与「**凛冬**」（被冰冻的敌人阵亡 → 冰冻爆炸）、`statusDuration`、局外词条「电枢」「霜心」**本来就通**（冻伤 / 凛冬是 `tryApplyFrost` 的**下游**，宠物挂的减速照样触发）：
  - **雷电虫吃闪电线增伤**：`petSkillDmg()` 与普攻（`firePetBullet()`）统一乘新增的 `petEleLineMul()` —— `1 + min(ELE_SHARE_CAP, ELE_SHARE × (s.dmgMul − 1))`，取 **`ELE_SHARE = 0.5` / `ELE_SHARE_CAP = 0.5`**。折半 + 封顶的理由：「雷电伤害 +30%」**没有上限**（`lightning-dmg` 未挂 `canPick`），直接乘满等于「投电系 = 白赚一条武器线」（满技能 8.22 → ×1.9 = 15.6，与一条武器线持平），与宠物「辅助」的定位冲突。
  - **冰霜领域吃霜冻附魔**：`slowMul` / `slowTime` 改「取大不叠乘」—— 强度 `min(0.45, 0.6)` 仍取宠物自身更强的那个（**不会被削弱**），时长 `max(1.0, 2.0)` 抬到 **2.0s**。刻意**不套**附魔的概率门（10~50%），因为领域的减速本来必中，套概率门反而是负体验。
  - 落点只有两个函数：**不给 12 条技能加 `ele` 字段** —— 元素归属直接读现成的 `PET_DEFS[pet.type].elem`（每只宠物的 3 条技能同属一个元素）。又因为 `petSkillDmg()` 在**释放瞬间**就把结果存进 fx 的 `f.dmg`，所以**改一处即全覆盖**（含雷电场 / 冰霜领域这类持续技的每 tick 结算），不必改 `petFxTick`。
  - 无存档影响：`PET_DEFS` / `PET_SKILLS` 是静态定义，存档里存的是**技能 id 字符串**，`normalizeMeta()` / `validateMeta()` 不遍历技能字段 → **不需要 `META_SCHEMA + 1`**；也不新增随机取值、不碰三条随机流。

### 调整

- **主页按钮文案**跟随模式（`开始游戏 · 标准`）；模式选择卡未解锁时置灰并标「标准通关后开放」。
- **老存档兼容**：`bestWave ≥ 20` 的账号在 v1 → v2 迁移里直接视为「标准模式已通关」，**无尽模式立刻可选**，不用重打一遍。
- **写入失败的提示**与「未同步到云端」共用同一条浮层（`setHint`），并区分文案。
- **导入存档**（开发者模式）也走 `migrateMeta()`，结构不合法直接拒绝导入并回执原因。
- **「牛来」造型按电影原样重做成低模**：V1.31 那版画成了圆润卡通的「黑白花奶牛」，和 2026 年那部《牛来》正片里的低模小牛对不上。现在按电影造型重画（新增 `shadeHex()` 生成「受光 / 主面 / 背光」三档纯色面，体积全靠**面与面之间的硬边色差**，`drawCowCharacter` **全函数不再使用任何渐变**，`lineJoin` 改 `miter`）：
  - **体块**：八边形**方头**（左右对称）+ 七边形躯干、方柱四肢不带关节、直尾杆 + 三角尾穗；
  - **电影里最标志性的三处**：**圆点眼**（一颗纯色圆点 + 一点高光，不做睫毛、不做瞳孔分层）、**肉色厚嘴唇的大鼻镜**（含两个方鼻孔）、**两脚站立**（电影设定是「现实段落四脚着地、梦境段落两脚站立」）；
  - **耳**改成硬边梯形并**画在头之下** —— 耳根伸进头里由头盖住，既不会露出接缝，也不会在脸里留下一道多余的描边；**角**改成两块硬边三角；衣领 / 腰带 / 围巾统一改硬边多边形；
  - 途中修掉三处观感问题：尾巴原先从臀部**向上**画，和左臂同色同列连成一根「粗胳膊」→ 改为**向左后下方垂**；呆毛、躯干原先左右不对称 → 都改成对称；受光面 / 背光面原先带描边，会在脸内侧留一道多余的墨线 → 改成**只填色不描边、最后统一补一圈外轮廓**。
- **四把枪的模型重做**：之前每把枪只有色块、没有轮廓，而局内角色半径只有 **14**（缩放 0.7 倍），枪会糊成一团、分不出是哪把。现在四把枪**都带一圈墨线**（与角色的描边语言统一），并各自补齐结构：
  - **步枪**：木质枪托（带受光面）+ 机匣 + 握把 + 直弹匣 + 长护木 + 枪管 + 消焰器；
  - **霰弹**：上下**双管**（中间留一道缝）+ 木质泵柄 + 机匣侧挂**三颗黄铜弹壳**；
  - **激光机枪**：方盒机匣 + **发光能量核心**（品红）+ 直弹匣 + 开槽散热套 + 枪口能量；
  - **狙击**：超长枪管 + 制退器 + **瞄准镜**（物镜 / 目镜两片镜片）+ **两脚架** + 腮托 + 拉栓。
  - 细微件（准星 / 枪管箍 / 弹匣底板 / 散热孔 / 侧挂弹壳 / 镜面反光 / 两脚架 / 拉栓）仍只在 `detail`（半径 ≥ 22，即角色页预览）时绘制，局内小尺寸只保留主体结构。

### 修复

- **目标优先级此前只对宠物生效**（V1.31 埋的坑）：自动攻击取目标有 4 处没接上 `pickTarget()` —— **武器**（`updateWeapons`，也就是主要输出）、**宠物技能**落点（`castPetSkill`）、**火球触发**（`triggerFireball`）与**角色朝向**（`drawSoldiers`）都还在各自取「最近的敌人」。结果是切到「首领优先」只有宠物普攻听话，武器照旧打贴脸小怪 —— 正是需求 13 想解决的问题。现在四处统一走 `pickTarget()`，并补了三条**穿透到子弹实际朝向**的断言（按 `bullets[0]` 的 `vx/vy` 反推打的是谁：最近 → 小怪、首领优先 → 首领、最强 → 首领）。
- **主循环不再重复同步暂停 / 目标按钮的显隐**：以前 `loop()` 每帧按 `state !== 'playing'` 写一次 `.hidden`，与各处手工 `.hidden` 各自为政；现在显隐由 `setState()` 统一负责，消除「两处规则不一致」的隐患（顺带修掉「状态已是暂停、遮罩却没弹出来」这类漏写）。
- **修正宠物实测数据的口径标注**：`需求方案.md` 里那组「雷电虫 6.04 / 7.20 / 6.58、冰冻精灵 5.56 / 7.56 / 5.04」原先标成「**仅技能伤害**的 DPS」，本轮复测时确认它其实是**宠物总输出＝普攻 + 技能**（把普攻 4.8 也算进去了：6.04 − 4.71 ≈ 1.3，与「关掉普攻只算技能」的 **1.47** 吻合）。口径说明已改正；基线重测 **6.04 / 7.20** 与旧记录**逐位一致**，所以旧数据仍然可用、可直接和新表对比。

## v1.30 · 2026-09-22 —— 装备「洗练」+ 词条口径重做（数值分档 / 独立乘区 / 机制型词条）

### 背景

V1.29 把装备拆成护甲 / 饰品 / 物品三槽位后，词条还是「解锁时一次性发满、数值写死、重铸只换种类」——既没有追求感，数值上又和局内卡挤在同一个加算区。这次补三件事：

1. **词条要有追求**：改成**逐条洗练解锁**（最多 3 条）+ **数值分三档**，洗练时可以**锁定**已经满意的词条（代价是费用翻倍），于是「刷到 T3 + 好组合」成了一个长期金币出口。
2. **+8% 不该被稀释**：局内卡都在同一个加算区里（强力子弹 +30% / 力量权柄 +50% …），一条装备词条的相对收益会被越压越小 —— 实测手上已有「力量权柄 +50%」时，+12% 的词条实际只值 **+8%**（1.50 → 1.62）。改走独立乘区后就是实打实的 **+12%**（1.50 → 1.68）。
3. **补机制型词条**：纯数值词条容易被稀释、也没有 build 感，加 3 条靠机制生效的。

顺带修掉一个与文案不符的实现：**力量护符 / 狂战戒指写着「造成伤害 +15% / +30%」，实际只加到子弹线**。

### 新增

- **装备洗练（每件最多 3 条词条）**：

  | 规则 | 数值 |
  |---|---|
  | 初始条数 | **1**（与装备档次无关，V1.29 是按品质发 1 / 2 / 3 条） |
  | 第 2 / 3 条 | 累计洗练 **5** 次 / **15** 次解锁 |
  | 单次花费 | **200 金币** × 2^(锁定条数)：不锁 **200** / 锁 1 条 **400** / 锁 2 条 **800** |
  | 锁定 | 免费切换；锁定的词条在洗练时**保留**（id 与档位都不变），未锁定的全部重 roll |
  | 不重复 | 洗练时排除该件已有的词条，**同一件永不重复** |

- **词条数值分三档**：带档位的词条按 **55% / 32% / 13%** 抽 `T1 / T2 / T3`（高档稀有），中档就是 V1.29 的旧值（如 弹道 **+6% / +8% / +12%**、壁垒 **+10 / +15 / +22**、铁壁 **×0.95 / ×0.94 / ×0.92**）。灵巧（开局重抽 +1）与破势是定值，没有档位。
- **3 条机制型词条（不吃数值稀释）**：
  - **破势**（定值）：**子弹穿透 +1**，开局直接加到携带的武器上。
  - **裂甲**（+15% / +25% / +40%）：对**带护盾**的敌人加伤，在护盾吸收之前乘。
  - **荆棘**（50% / 80% / 120%）：受伤时对周围 **90px** 内的敌人造成**该次伤害的**对应比例 —— 按受伤比例而不是定值，随敌人强度自然成长，不会像定值反伤那样贬值。

### 调整

- **数值类词条改走独立乘区**：弹道 / 元素 / 召唤 / 兽伴不再进 `dmgBonus` 加算区，而是乘进 `dmgBase`（词条之间相加、整体作为一个独立乘区）；「破甲」也从 `stats.vuln` 挪到独立的 `stats.vulnGear`，在易伤加算区之后再乘一次。**同一件装备的词条数值不变，但相对收益提高了**。
- **饰品主属性改成四类伤害通吃**：`damageDealt` 现在同时乘上 `dmgBase` 的子弹 / 元素 / 召唤物 / 宠物四项，力量护符（×1.15）与狂战戒指（×1.3）对元素线、召唤线、宠物线一样有效。
- **解锁装备只给第 1 条词条**（V1.29 是按品质发 1 / 2 / 3 条），其余靠洗练解锁；开发者模式「一键解锁全部」改成只补缺的词条、**不重置**已有洗练进度。

## v1.26.2 · 2026-09-21 —— 首领不再「在原地打转」；冲锋指示带前段追踪、后段锁定

### 背景

两处首领表现被同时反馈为「在原地打转」，实测都成立：

1. **走位**：`moveBoss` 的径向修正是「出了 `orbitR ± 60` 的死区才给满速」的开关式 —— 只要距离落进死区就完全不修正，于是首领停在**死区边缘**（实测冲锋者 **206**、分裂者 **60**，目标分别是 150 / 110）。同时绕行方向每 2.5~5.5s 就翻转，而首领只有 28~40 移速（绕一圈要 20~75 秒），**一段弧都走不完就折返**：四种首领 20 秒的**净**绕行角度分别是 -25° / -34° / -5° / -47°，等于原地抖。
2. **冲锋指示带**：蓄力 1 秒里首领完全不移动，而 `aimBossCharge` 以 6 rad/s 全程把方向转向玩家 —— 实测**每帧瞄准误差恒为 0°**，指示带永远精确指着玩家：既读不出该往哪躲（横着跑它也跟着转），视觉上又是「站着原地转圈」。

检查其他首领时又发现一个连带 bug：**分裂者的突进撕咬从来没触发过**。它「已贴脸就不突进」的阈值是 `e.r + 70 = 116`，而它自己就停在 `orbitR = 110` —— 永远落在阈值内，每次都被判成「贴脸」，招牌技能成了死代码。

### 修复

- **走位收敛**：径向修正改为**按偏差比例**给（`radial = clamp((d - orbitR) / BOSS_MOVE.band, -1, 1)`，`band` 60 → 45），越接近目标距离修正越小，首领真正停在 `orbitR` 上；绕行方向翻转间隔 `flipMin / flipMax` **2.5~5.5s → 6~11s**，让它至少走完一段看得出来的弧再折返。
- **蓄力瞄准前段追踪、后段锁定**：新增 `BOSS_SKILL.trackFrac = 0.4`，蓄力前 40% 仍按 6 rad/s 转向玩家（冲刺不至于白放），之后方向锁死、指示带跟着停住。用**比例**而不是固定秒数：二阶段连冲的前摇只有 0.45s，固定 0.4s 等于几乎不锁定。锁定后「指示带 = 真实落点」这条不变（冲刺复用的是同一个方向向量）。
- **分裂者撕咬阈值**：`e.r + 70`（116）→ `e.r + S.soldierR + CONTACT_PAD`（66），即「只有真的贴到身上（进入接触伤害范围）才不突进」。

### 验证

- **稳定距离**（玩家静止、各跑 20~30 秒）：冲锋者 206 → **159/150**（冲刺落地后会短暂贴近，属正常）、弹幕者 293 → **296**、召唤者 300 → **300**、分裂者 60 → **109**（目标 110）。

两头的问题：① 穿透只有步枪（最多 3 次）与狙击枪（最多 4 次）能拿，散弹 / 机枪拿不到，卡池也碎；② 散弹的弹丸全都瞄向 `converge = 110px` 处的一个点，**弹道先交叉再分散** —— 5 发在 110px 内挤成一束，于是从贴脸到 110px 都能吃满一整轮伤害（实测 42 / 42 / 42 / 42 / 42），观感上也像子弹互相穿过。

### 调整

- **「武器穿透 +1」→ 通用「子弹穿透 +1」**：下架 `rifle-pierce`（最多 3 次）与 `sniper-pierce`（最多 4 次），换成一张全武器通用卡 `bullet-pierce`：**穿透 +1，代价是子弹伤害 ×0.9（独立乘区，与「弹丸 +1 组」同一套算法）**，**最多 4 次**（复用 `canPick` / `markPick`）。散弹 / 机枪现在也能拿穿透。
- **进化前置顺势改名**：穿甲连射（步枪）与湮灭狙击（狙击枪）的 `req` 本来就是「穿透 ≥ 3」，前置说明从「步枪穿透 3 级 / 狙击枪穿透 3 级」改为「**子弹穿透 3 级**」（狙击枪自带穿透 1，再叠 2 张即达标），条件本身不变。
- **点燃 / 减速的基础时长上调**：`BURN_TIME` **2s → 3s**、`FROST_TIME` **1s → 2s**（冰刺的霜冻与宠物点燃各用自己的时长，不受影响）。单次点燃总伤害 12 → **18**（满「严重灼伤」18 → **27**）；状态覆盖率上限随之抬到 点燃 **86%** / 减速 **80%**（Boss 抗性 1.5s 下 67% / 57%）。
- **散弹弹道修正**：删掉 `WEAPON_DEFS.shotgun.converge` 与 `fireWeapon` 里的收束分支，改成「**每颗弹丸在散布锥里占一个固定角度**（按编号从一侧排到另一侧）+ 枪口横向错开 + 少量抖动」，且**抖动幅度限制在相邻弹丸角间隔的一半以内**（`gap = spread / (弹丸数 - 1)`，抖动 ±0.4·gap）——这样弹丸的编号顺序在任何距离都不会反转，**弹道永不交叉**；收束期间那颗「保底全中」的效果随之消失。
- **散弹加强（6 枚弹丸 + 更高单发）**：`dmg` **6 → 7**、`baseCount` **5 → 6**，一轮 **30 → 42（+40%）**。这是给上一条「弹道不再交叉」的补偿——修完之后中距离跌得太狠（170px −41%），于是既加弹丸又加单发，把整条曲线抬回并**略超**修改前的水平（实测全距离 **+34%~+40%**）。散弹依旧是纯近战爆发：贴脸 **40.3 DPS**（比机枪 24.5 高 64%）换 110px 外快速衰减（170px 只剩 **10.2**）。

## v1.20 · 2026-09-21 —— 允许首领碾碎挡路的建筑：不再「只有冲刺才能脱身」

### 背景

首领体型大（`r = 40`）、走位全由 AI 驱动，一旦抵住木桶 / 箱子 / 石柱就会被障碍物推出逻辑顶在原地，只能等它自己触发冲刺才挪开——打起来会出现「首领一直抵着柱子不动」的观感问题。

### 新增

- **首领碾压 `crushObstaclesByBosses(dt)`**：首领（含冲刺途中）与障碍物接触时分别处理——
  - **木桶 / 箱子 / 石柱**：**直接碾碎**，无视血量（石柱的 `hp = Infinity` 也不再挡得住）。掉落照常走 `damageObstacle(o, 0, true)` 的新增 `force` 分支：木桶 +3 金币 · 8 经验、箱子 +5 金币 · 12 经验、石柱无掉落。
  - **树木**：**不碾碎**，改为**加速苏醒**——新增 `FLORA_CFG.tree.bossAggroMul = 3.5`，首领贴着树木时苏醒进度按 3.5 倍速积累（同样读条、外圈进度环照常显示），实测**无人靠近 1.22s / 有小兵在旁 0.78s** 苏醒为树怪，首领自然脱身。
  - **只为首领开启**：普通小怪与精英不会碾碎任何东西；石柱对子弹仍是无敌掩体（`damageObstacle` 不带 `force` 时照旧直接 `return`）。
- 判定挂在 `update()` 里 `updateEnemies(dt)` 之后、`resolveEnemyCollisions()` **之前**：推出逻辑会把首领推离障碍物，晚一帧判就永远不再接触了，所以必须先判。

### 验证

- **定点测试**：首领接触木桶 / 石柱 → 当帧摧毁（木桶 +3 金币 + 1 个经验球、石柱 0 掉落）；接触树木 → **1.22s** 苏醒出 1 只树怪，小兵进入 80 范围内时 **0.78s**。

## v1.19 · 2026-09-20 —— 闪电重做：触发判定改「窗口制」（硬间隔 0.35s → 0.30s），并移除全部「闪电触发概率」类选项

### 背景

**其一（窗口制）**：想「把落雷频率略微调高一点」，但改 `LIGHTNING_MIN_INTERVAL` 完全没反应。扫参后发现**旧机制下这个数字只有两档有效**：

| 硬间隔 | 机枪满层实测 |
|---|---|
| 0.40 | 1.82 次/秒 |
| 0.35 | 2.72 次/秒 |
| **0.30** | **2.72 次/秒** |
| 0.25 | 2.72 次/秒 |
| 0.20 | 2.72 次/秒 |
| 0.175 | 5.43 次/秒 |

原因是旧的「命中时 roll + `lightningCdT` 拦截」：判定机会只在**子弹命中那一刻**产生，而机枪每 0.175s 才有一轮子弹，于是 cd 还没走完的那次机会被白白浪费，实际落雷间隔被量化成**开火间隔的整数倍**——硬间隔只要落在 `(0.175, 0.35]` 里，一律等效 0.35s。

**其二（移除概率类选项）**：闪电的触发概率走的是「**命中敌人时按概率触发**」，且「额外闪电」叠到 4 层就是 **100%** —— 所有「触发概率 +X%」的加成在满层构建下**本来就是空效果**（100% 之上无法再加），只会占据奖励格子、误导选卡。故整条线一并去除，概率只留一条来源。

### 调整

- **触发判定改为「窗口制」**：一次落雷之后的 `LIGHTNING_MIN_INTERVAL` 秒算一个窗口，窗口内只要有子弹命中过敌人（`lightningPending` 布尔标记）就在窗口结束时判定一次。于是 **落雷频率 = max(硬间隔, 武器开火间隔)**，可以连续调。
  - `rollLightningOnHit(v)` 只负责「记下这轮打到了人」，判定抽离到新的 `tryLightning()`；`updatePendingLightning()` 在窗口结束（`lightningCdT <= 0 && lightningPending`）时补一次判定。

- **硬性间隔 `LIGHTNING_MIN_INTERVAL` 0.35s → 0.30s**：现在这个数字是真起作用的——机枪满层 **2.72 → 3.15 次/秒（+16%）**。

## v1.18 · 2026-09-20 —— 波次改固定 20s 计时：不再等清场，出怪走纯速率

### 调整

- **波次推进从「清场制」改为「计时制」**：旧规则是「本波配额刷完 **且** 场上清空」才进下一波，节奏完全被玩家的清怪速度决定——清得快就越推越快、清不干净就永远卡在同一波。现在每波固定 **`WAVE_TIME = 20s`**，到点即 `wave++`，**不看场上还剩多少**。
  - 「清空」不再是唯一的喘息窗口，玩家强度体现在「能不能压住不断累积的怪」。
  - 存档字段随之变化：`waveSpawned` / `waveSize` 删除，改为 `waveT`（旧存档没有该字段时按 0 处理，不受影响）。
- **出怪从「每波配额」改为「纯速率」**：新增 `spawnInterval()`，删除 `spawnEnemy` 的每波配额门控。
  - `spawnInterval() = max(0.10, 4.8 / pace)`，`pace = (1 + 0.35 × (波次 - 1)) × min(2.0, spawnScale())`。
  - 每波实际出怪量 ≈ `20s ÷ 间隔`：

    | 波次 | 1 | 5 | 10 | 20 | 30 | 50 |
    |---|---|---|---|---|---|---|
    | 出怪间隔 | 4.8s | 2.0s | 1.16s | 0.36s | 0.22s | 0.13s |
    | 每波约 | 4 只 | 10 只 | 17 只 | 55 只 | 93 只 | 151 只 |

  - `spawnScale()`（世界成长「出怪 +12%/Boss」）**只作为出怪间隔的加速项**（除数，封顶从 1.6 倍提到 **2.0 倍**），不再决定每波总怪量。
- **新增同屏上限 `MAX_ALIVE = 180`**：刷到这个数量就先停手，等玩家清掉一批再继续——防止后期堆积到卡顿（顺带避免敌人分离的开销失控）。
- **首领存活 / 场地封锁期间波次计时暂停**：否则上一只首领没死就会刷出下一只，`openBossArena()` 还会把场地重新圈一遍。精英波不冻结计时。首领与精英仍是**波初投放**（第 10/20/30… 波首领、第 5/15/25… 波精英）。

## v1.17 · 2026-09-20 —— 敌人碰撞体积：怪不叠怪、怪不叠人；镰刀改线段扫掠判定

### 新增

- **敌人碰撞体积**：每只敌人的 `r` 现在就是碰撞半径，进图后受三重约束（`resolveEnemyCollisions()`）——
  - `separateEnemies()`：**怪物之间互不重叠**。按半径反比分配推开量（体型越大被推得越少）。
    - **首领不被小怪推动**（`wa = 0`）——否则一堆小怪挤上来会把冲刺轨迹推歪。
  - `separateEnemiesFromSquad()`：**怪物与玩家不重叠**，把敌人逐个推出每个小兵的碰撞圈（`S.soldierR = 14`）。
  - 原有的 `resolveObstacleCollision()` 保留，木桶 / 箱子 / 石柱 / 树木照旧阻挡；**并且改成前后各解一趟**——中间的推挤会把敌人挤进树木 / 石柱里（实测最大穿障深度 32.5），收尾补一趟后降到 **5.79**、深穿帧次 7 → **0**。穿障比轻微重叠显眼，所以让障碍物优先级最高。
  - **两个约束交替迭代 2 趟**（而不是「先跑完怪互推、再统一推出玩家圈」）：小兵会把敌人压成一层「壳」，壳上装不下时两边会互相破坏对方的结果，交替投影收敛更彻底——40 只怪全挤在玩家身上的极端场景，最大重叠深度从 4.91 降到 **3.33**（世界单位，≈2.5 屏幕像素）。

- **飞剑**无需改动：它本来就是按本帧位移线段做贯穿判定（点到线段距离 < 剑身判定 + `e.r`），天然满足「掠过碰撞体积就造成伤害」。

- **统一伤害乘区的下限层级**：下限改为**只作用在「加算区」这一层**（`dmgBase.X × max(下限, 1 + Σ加成)`），独立乘区（`w.dmgMul` / `s.dmgMul` / `pet.dmgMul`）一律只做纯乘、不再带下限。四路取值明确：子弹 / 召唤 / 宠物 0.3，元素 0（保留「可被归零」这一设计杠杆）。
  - 旧 → 新（`refreshSummonMul`）：`max(0.3, (1 + dmgAdd) × dmgMore)` → `(1 + dmgAdd) × dmgMore`。此前「数量 +1」类卡的 ×0.9 叠到 12 张（0.9¹² ≈ 0.282）就会触底失效、进化卡的 ×1.3~1.4 也被同一个下限截断，现在按原值生效（实测 12 张后 `dmgMul = 0.2824`，再乘进化 1.4 得 `0.3954`）。
  - 旧 → 新（`recalcDamage`）：`max(0.3, dmgBase.bullet × (1 + Σ子弹))` → `dmgBase.bullet × max(0.3, 1 + Σ子弹)`。此前局外装备（力量护符 ×1.15）会被极端减益一起压到 0.3，现在保留装备倍率（实测 1.15 × 0.3 = **0.345**，旧为 0.3）。
  - 宠物弹丸不再用 `max(1, stats.elementalDamage)` 兜底，改为直接吃 `stats.elementalDamage`，与元素线同规则。
  - `pet-dmg` 卡（`baseMul × max(0.3, 1 + dmgAdd)` → `baseMul × (1 + dmgAdd)`）与 `restoreRun`（召唤物 / 宠物乘区改为**无条件重算**，避免旧存档里带着旧下限的 `dmgMul` 卡住）同步跟上。

### 新增

- Boss 奖励新增一对**互斥的路线取舍卡**（参考 20 Minutes Till Dawn 的取舍型 Synergy：一次性、幅度写死、代价只扣一个固定百分比且之后仍可补回）：
  - **元素专精**：元素伤害 +50%、子弹伤害 -30%。
  - **实弹专精**：子弹伤害 +50%、元素伤害 -30%。
  - 两张幅度对称，均需有元素来源；带 `once: true`（拿过不再出现）与 `exclusive: 'dmg-route'`（同组已选则对方不再出现；同一波奖励里选走一张，会把另一张从当次候选一并撤出）。
  - 新增 `hasExclusivePicked(group)` 供 Boss 奖励去重使用。
- `pickBossReward` 改为选卡后过滤候选并重渲染，从而实现「同波二选一」。

### 修复

- 修复 **Boss 奖励可重复拿同一项**：此前不查 `appliedIds`，每波 Boss 都可能再拿到同一张 Buff。
- 修复 **「子弹 +50% / 元素归零」与「元素 +100% / 子弹 -50%」两张都拿会互相抵消**：两张都写在同一个加算区（`-1` 与 `+1` 相抵、`+0.5` 与 `-0.5` 相抵），结果玩家花两个奖励位拿到「双双归零」。改为互斥二选一后该状态不可能出现，顺序敏感问题也一并消失。
- 修复 **Boss 奖励卡文案歧义**：旧文案「已累积的元素加成清零」容易被读成「回到无加成」，而实现是伤害倍率归零；新文案直接写清增减幅度。

### 验证
